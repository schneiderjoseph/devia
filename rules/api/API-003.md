# API-003 — Breaking changes are versioned

**Requirement:** Removing a field, changing a type, tightening validation or changing a status code on a published endpoint MUST ship behind a new version or a documented deprecation window with a migration note.

**Bad:** A field is renamed and every existing client breaks on deploy.

**Good:** The new field is added, both are served through the deprecation window, then the old one is removed.

## Validation

- Consumers identified
- Deprecation window or new version documented
