# API-002 — Errors use one envelope and a stable code

**Requirement:** API errors MUST share a single response shape with a stable machine-readable code, an HTTP status that matches the semantics, and a message safe to display.

**Bad:** One endpoint returns `{error: 'x'}`, another a plain string, a third a 200 with `success: false`.

**Good:** `{ error: { code, message, details? } }` everywhere, with 4xx for client faults and 5xx for ours.

## Validation

- Error shape identical across the endpoints touched
- Status codes match semantics
