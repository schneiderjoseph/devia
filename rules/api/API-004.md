# API-004 — Retryable state changes are idempotent

**Requirement:** Any operation a client or provider may retry — payments, submissions, webhooks, queue consumers — MUST be safe to execute twice, through an idempotency key or a natural unique constraint.

**Bad:** A double-clicked submit creates two orders.

**Good:** The request carries an idempotency key; the second attempt returns the first result.

## Validation

- Test: the same request twice produces one effect
