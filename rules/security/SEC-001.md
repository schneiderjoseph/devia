# SEC-001 — Server-side authorization on every sensitive operation

**Requirement:** Every operation that reads or changes data belonging to a user, tenant or role MUST verify authorization on the server, on every request, from the session identity — never from a client-supplied identifier.

**Bad:** The endpoint trusts `userId` from the request body, or the UI simply hides the button.

**Good:** The handler derives the actor from the session and checks the actor's right to that resource before doing anything.

## Validation

- Test: actor A cannot reach actor B's resource
- Test: role without permission gets 403, not 200

## Lifecycle

- Status: `active`
- Priority: `P0`
- Exceptions: `none`
